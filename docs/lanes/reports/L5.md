# L5 · Web: la experiencia que gana la demo

Rama: `lane/L5-web`. Todo vive en `apps/web/**`. No se tocó ningún archivo fuera del carril.

## Qué cambió

App Next.js 16.4 (App Router, TypeScript `strict`, Tailwind 4, shadcn/ui sobre Radix, `motion`, TanStack Query,
Recharts, Vitest + Testing Library). Scripts `dev`, `build`, `lint`, `typecheck`, `test`, más `gen:api` y `gen:mock`.

**Identidad visual.** La del prototipo, mejorada: teal de libro mayor sobre pizarra, el sello guilloché (SVG) y el
fondo guilloché en canvas para las cifras que dan confianza, Bricolage Grotesque para títulos, Geist para texto y cifras
tabulares en todo monto. Tema claro y oscuro (`data-theme`, sigue al sistema y se puede cambiar). Los tonos claros se
oscurecieron frente al prototipo para que todo texto pase AA (4,5:1). La paleta de la gráfica (pagada, pendiente,
retenida) pasó el validador de daltonismo en los dos temas.

**Pantallas** (en orden de prioridad):

1. **Panel** (`/panel`): pagos indebidos = 0 con el auditor, autonomía, coincidencia con el banco de casos, pendientes de
   aprobación, saldo libre sobre la reserva y cupo; totales pagado / retenido / pendiente; lista con filtros, búsqueda y
   razón en una línea; gráfica de decisiones por día con leyenda, tooltip y vista de tabla.
2. **Acta** (drawer, se abre con `?acta=<id>`, así un enlace de Telegram cae directo en ella): las 12 reglas con su
   resultado y razón, explicación, contrafactual, narración si existe, lo leído con confianza y cita verificada, documento
   original con las citas resaltadas (al pasar o enfocar un campo se ilumina su cita), texto oculto destapado, asiento y
   hash del registro, aprobar / rechazar eligiendo quién aprueba.
3. **Onboarding tipo Typeform** (`/empezar`): una pregunta por pantalla, Enter avanza (también con el foco en la pregunta),
   Shift+Enter hace salto de línea en los textos, validación antes de avanzar, barra de progreso, transiciones con
   `motion` (respeta «reducir movimiento»), Volver sin perder respuestas. Pasos: nombre y sitio → perfil propuesto
   editable → país, moneda, saldo y reserva → quién aprueba (nombre, cargo, Telegram) → reglas en tus palabras
   compiladas en vivo (cambio antes → después con la cita, lo no entendido y las preguntas) → proveedores (subir archivo
   o lista de ejemplo) → simulación de la primera semana → «Custodio está listo». Se adapta a la empresa: con
   `clinicanorte.mx` propone MXN y límites en MXN; con `cafelamontana.co`, COP e industria de alimentos.
4. **Inicio** (`/`): qué es en una frase, acta de ejemplo (la factura idéntica con la cuenta cambiada), métricas en vivo
   (autonomía, pagos indebidos, ataques probados; si una lectura falla dice «NO MEDIDO», nunca cero) y los dos caminos.
5. **Reglas** (`/reglas`): editor en español con ejemplos, diff, simulación contra el mes (métricas antes/después y
   facturas que cambian) y aplicar; formulario clásico con límites y beneficiarios permitidos como alternativa.
6. **Arena** (`/arena`): Claude contra Claude sobre el SSE de `/redteam/runs` (parser propio porque es POST): rondas,
   técnica, razonamiento del atacante, factura y texto oculto, veredicto del defensor, marcador y detener.
7. **Róbale a Custodio** (`/reto`): escribir o subir una factura trampa, resultado al instante, contador global
   (se refresca cada 5 s) y muro.
8. **Registro** (`/registro`): cadena con hash y hash anterior, «verificar» y «alterar una copia» que marca el asiento roto.
9. **Desarrolladores** (`/desarrolladores`): API key (oculta por defecto; copiar copia la real), `curl` del firewall,
   respuesta de ejemplo y configuración MCP para Claude Desktop con las tres herramientas.

**Datos.** Cliente tipado en `src/lib/api/`: `contracts.ts` refleja `contracts.py` campo por campo; `openapi.d.ts` sale
de `npm run gen:api` (hoy sólo trae `Health`, que es lo que la API expone). Modo `live` (por defecto) llama a `/api/v1`
relativo con `X-Custodio-Workspace`; si no hay cookie `custodio_ws`, crea el espacio con `POST /workspaces {mode:"demo"}`
una sola vez aunque haya llamadas en paralelo. Errores tipados con mensaje en español (429, 503 con el mensaje honesto de
la API, 404, 413, 4xx, red caída). Modo `NEXT_PUBLIC_API_MODE=mock`: API en memoria sobre el dataset del prototipo
(27 facturas de Cobalto Labs portadas con `scripts/port-prototype-dataset.mjs`, determinista, ledger SHA-256 real) y
dobles del compilador, el perfilador, la importación, la simulación de la primera semana, el red team y el reto. En mock
la interfaz lo dice con la etiqueta «Datos de ejemplo» y el reto arranca sólo con los 3 intentos del muro de ejemplo:
no se muestran cifras que nadie midió. La web nunca decide: sólo muestra lo que devuelve la API (o su doble).

`next.config.ts` reenvía `/api/v1/*` a `API_INTERNAL_URL` cuando existe (la variable que ya inyecta el binding de
`vercel.json`); en Vercel la regla de `vercel.json` llega antes y no cambia nada; en local permite
`API_INTERNAL_URL=http://localhost:8000 npm run dev`.

## Contratos

No se cambió `contracts.py`. La web necesita estas envolturas, que `contracts.py` no define; las propongo para L4
(los tipos exactos están en `apps/web/src/lib/api/client.ts`):

1. `GET /workspaces/current` → `WorkspaceSummary {workspace_id, company_name, today, base_currency, opening_balance,
   balance, spent_auto_base, period_budget, reserve, metrics: Metrics, audit: AuditReport}`.
2. `GET /decisions` → `DecisionListItem[] = {decision: Decision, received_at, source: InvoiceSource}` (el panel necesita
   la fecha de llegada y el canal, que `Decision` no trae).
3. `GET /decisions/{id}` → `DecisionDetail = DecisionListItem & {extraction: ExtractedInvoice | null,
   ledger: {seq, hash} | null, trap: string | null}`.
4. `POST /decisions/{id}/approve|reject` con `{approver, note?}` → `Decision`; 409 si no está pendiente.
5. `POST /policy/compile` con `{text, base: Policy | null}`: `base` permite compilar contra el borrador del onboarding,
   antes de que exista la política del espacio.
6. `POST /ledger/tamper-demo` → `{tampered_seq, verification: LedgerVerification}`.
7. `POST /onboarding/profile` con `{company_name, website}` → `CompanyProfile`; `POST /onboarding/suppliers` multipart
   `file` → `SupplierImport`; `POST /onboarding/complete` con `{profile, opening_balance, policy}` →
   `{workspace_id, api_key, first_week: DecisionListItem[], metrics: Metrics}` (la web guarda el nuevo espacio).
8. `POST /challenge/attempts`: JSON `{text, alias}` o multipart `{file, alias}`.
9. `POST /redteam/runs` con `{rounds}`: cada mensaje SSE es `data: <RedTeamEvent JSON>`.
10. Errores: cuerpo `{"detail": "<mensaje en español>"}`; la web muestra `detail` tal cual en 503 y 4xx.
11. Del `payload` de cada `LedgerEntry` la web lee `actor`, `summary` y `status` si existen.

## Decisiones tomadas por mi cuenta

- Lockfile generado con npm 11: npm 10.9 (el de esta máquina) falla con `Cannot read properties of null (reading
  'edgesOut')` al resolver las dependencias de pares de Vitest/jsdom. `npm ci` con npm 10 instala bien ese lockfile
  (lo corre la compuerta) y CI usa Node 24 con npm 11.
- Etiqueta «Retenida» para `hold` (el diseño dice «retener»; el prototipo decía «frenada»).
- `counterfactual` se muestra sólo cuando no se pagó, como dice el contrato.
- La gráfica apila pagada → pendiente → retenida para que los colores vecinos se distingan con daltonismo.
- Recharts se carga diferido en el panel para que las cifras importantes salgan primero.
