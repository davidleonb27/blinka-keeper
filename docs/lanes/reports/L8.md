# L8 · Integración web ↔ API

Rama `lane/L8-integration`, rebasada sobre `origin/main` en `23255f1` (merge de L7). Sin PR: lo abre el dueño.

## Qué cambió

La web se había escrito contra su cliente simulado y en producción se caía: `/panel` lanzaba «TypeError: Cannot read
properties of undefined (reading 'checked')» porque `GET /api/v1/workspaces/current` no trae `audit`. Lo reproduje
igual contra la API local y contra https://custodio-blinka-green.vercel.app antes de tocar nada.

1. **El contrato sale de la API.** `apps/web/scripts/gen-api-schema.mjs` exporta el OpenAPI de FastAPI (`main:app`,
   `/api/v1/openapi.json`) y genera `apps/web/src/lib/api/schema.gen.ts` con openapi-typescript **7.13.0 (fija)**.
   `contracts.ts` pasó a ser alias de esos esquemas y `client.ts` deriva cada petición y respuesta por **ruta y método**
   (`ResponseOf<"/api/v1/workspaces/current", "get">`, `JsonBodyOf`, `FormOf`, `PathParamsOf`); el cliente real
   llama con esas rutas literales y el mock implementa la misma interfaz. Se borró `openapi.d.ts` (sólo traía `/health`).
   `scripts/check.sh` corre `npm run check:api` justo después de `npm ci`: regenera y falla si difiere del commiteado.
2. **Cada desajuste, del lado correcto** (lista completa abajo). API: resumen con `today`, `opening_balance`,
   `spent_auto_base` y `audit`; lista de decisiones con fecha de llegada y canal; compilar contra un borrador; evento
   SSE documentado. Web: acta, alterar copia, onboarding, reto multipart, cuerpo de alterar copia, registro, botón para
   procesar facturas. Mock: devuelve exactamente las formas de la API y sigue su flujo.
3. **Hidratación (#418)**: no lo pude reproducir (detalle en «Qué NO se verificó»); el e2e lo vigila en dos perfiles y
   comprobé que lo detecta.
4. **e2e**: `apps/web/e2e/` con Playwright 1.56.1 (`npm run e2e`, fuera de la compuerta) contra la API real.

## Qué NO se verificó

- **El #418 no lo reproduje.** Con Chromium 141: en producción, es-CO/Bogotá (también oscuro), en-US/Nueva York y
  es-ES/Madrid, con cookie de un espacio previo, recargas y navegación desde el inicio; en el build local, además,
  en-US/Tokio con movimiento reducido y pt-BR/Kiritimati oscuro con colores forzados, ambos con tema y API key en
  localStorage; y en `next dev` (que reporta cualquier desajuste de hidratación, incluidos atributos) en tres de esas
  combinaciones. Cero avisos de hidratación en todos. El HTML
  estático de cada página no contiene ninguna fecha, hora ni número formateado con `Intl` (los datos llegan después,
  en el cliente), y las lecturas de localStorage y del tema ya usan `useSyncExternalStore` con instantánea de servidor.
  No encontré una causa en el código, así que no cambié nada «por si acaso». Hipótesis no comprobadas: una extensión
  del navegador o la barra de Vercel que insertan nodos antes de hidratar, o HTML y JS de despliegues distintos (sin
  *skew protection*). Si vuelve a aparecer, `npm run e2e` contra ese despliegue o el mensaje sin minificar de
  `next dev` dirán en qué texto difiere.
- **Funciones con modelo contra Claude real**: NO MEDIDO. Este entorno no tiene `ANTHROPIC_API_KEY`; la única clave
  disponible (`LATZU_ANTHROPIC_API_KEY`) responde 400 «not scoped to a workspace». Compilar reglas, perfil, importar
  proveedores, red team, reto y narración se recorrieron con los dobles deterministas, no con Claude.
- Firefox, Safari/WebKit: sólo Chromium (el que trae el entorno). Postgres/Neon: sólo SQLite. El despliegue en Vercel
  con estos cambios: no desplegué.
- La lista de proveedores de ejemplo del onboarding (CSV con `;` y 5 columnas) la lee Claude en producción; el doble
  sólo entiende 4 columnas con coma, así que el e2e sube su propio CSV.

## Contratos

No cambié `contracts.py`: todo lo nuevo son modelos de rutas o servicios (`WorkspaceSummary`, `DecisionItem`,
`CompileRequest.base`) que reutilizan `AuditReport`, `Decision` e `InvoiceSource`. Tras el rebase, los tipos generados
ya no traen `telegram_chat_id` ni el canal `telegram` (L7) y la web compila sin ellos.

Propuesta para el dueño de `llm.py` (no es mi archivo): sin clave, el SDK lanza `TypeError` y la API responde **500**
«Error interno» en las rutas que llaman al modelo, en vez del 503 honesto `model_unavailable`. Medido con
`uvicorn main:app` sin clave: `POST /policy/compile` → 500, `POST /challenge/attempts` → 500,
`POST /onboarding/profile` → 500. `llm.structured` debería lanzar un `LLMError` propio cuando
`anthropic_configured` es falso.

## Decisiones tomadas por mi cuenta

- `GET /decisions` cambió de forma (de `Decision[]` a `{decision, received_at, source}[]`). Ningún otro consumidor del
  repo usa esa ruta (MCP y firewall van por servicios); si un agente externo la usa, es un cambio incompatible.
- El informe del auditor del resumen suma los veredictos guardados al decidir cada lote (`audit_blocked` y el motivo
  del acta) en vez de re-auditar con las reglas de hoy, que marcaría como indebidos pagos legítimos bajo reglas viejas.
  `checked` = pagos hechos + pagos detenidos; `improper_payments` coincide con `metrics.improper_payments`.
- `spent_auto_base` del resumen es lo que el agente pagó solo en el mes en curso, historial incluido: lo mismo que R11
  sumará en el próximo lote.
- Dependencias de desarrollo nuevas en `apps/web`: `@playwright/test` **1.56.1** (fijada a la versión del Chromium que
  trae el entorno) y `openapi-typescript` fijada a **7.13.0**. El lockfile se regeneró con npm 11 (como pide L5) y
  `npm ci` con npm 10.9 lo instala bien.
- El texto del panel sobre el auditor dice «los N pagos de este espacio» en vez de «que Custodio hizo solo», porque
  también revisa los aprobados por una persona.
- Las estadísticas del reto se piden sin cabecera de espacio (la API no la usa) para no crear un espacio demo sólo por
  abrir `/reto`.
